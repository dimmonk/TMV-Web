A — Site-wide blockers (all resolved)

Each lived in a shared component or a repeated pattern, so each fix cleared many pages at once.

✓ FixedHeader now collapses to a mobile menu (was Critical — nav ran off screen)

The header was a single non-wrapping row of logo + six links + “New here?” + Book Now, sized for a 1200 px canvas, so on a phone the links and button slid off the right edge. No hamburger, no breakpoint.

Done → SiteHeader.dc.html now shows a hamburger below 820 px that opens a full-width dropdown with all six links + “New here?”; only the logo and Book Now stay on the bar (the wordmark hides below 460 px so nothing overflows on small phones). Applies to all 13 pages.

✓ FixedFooter now stacks (was a fixed 4-column grid)

SiteFooter used grid-template-columns:1.6fr 1fr 1fr 1fr with no breakpoint, so on a phone the four columns crammed into ~90 px each and the address, hours and links wrapped into two-word fragments.

Done → SiteFooter.dc.html now drops to 2 columns under 720 px and 1 column under 440 px.

✓ FixedSplit heroes & info panels now stack (were hard two-column)

Five page heroes (Home, Train, Camps, Events, About) plus the shared SiteHero used a hard 1.05fr .95fr split with no breakpoint, squeezing the headline column to ~190 px beside a postage-stamp image.

Done → each hero and SiteHero, plus the split info panels (Home/About “Find us”, Camps “A day at camp”), now collapse to a single column under 820 px via a shared .pg-2col rule — image drops below the text.

✓ FixedDisplay type is now fluid (was frozen at desktop size)

There wasn't a single clamp() on the site; hero titles were pinned at 58–68 px, so at 390 px a big word nearly filled the width and headlines broke awkwardly.

Done → every hero H1 across all pages now uses clamp() (e.g. clamp(40px,9.5vw,60px)), and the shared SectionHeader title scales clamp(23px,5.4vw,34px), covering most H2s in one place.

C — What was already working (leave alone)

The card grids all reflow. Classes, camps, booking options, store items, reviews, coach cards, notes — nearly every content block uses repeat(auto-fit,minmax(…,1fr)) and drops to one column on a phone with no extra work.

Schedule is purpose-built for mobile. Below 768 px it swaps the week grid for a day-grouped list (.embed-mobile) — the pattern the rest of the site now follows in spirit.

CTAs are thumb-sized. Primary actions use ~16 px padding and clear the 44 px tap-target minimum; the header links are now in the menu, so they're no longer a hit-target concern either.

D — What's left

  1. Real-device pass at 360–430 px. Code + a Home screenshot are verified; walk the other 12 on an actual phone (or devtools device mode) to catch any leftover fixed-width oddity.
  2. Landscape / small-tablet (600–820 px). Confirm the 820 px breakpoint feels right in the gap between phone and desktop — nudge if a hero looks awkward mid-range.
  3. Menu polish (optional). The header dropdown works; consider locking body scroll while it's open and an outside-tap-to-close if you want it to feel more app-like.
